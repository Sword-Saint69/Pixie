# Pixie (gotohp-rs core)

**Pixie** is the Flutter UI over the `gotohp-rs` Rust core — a reimplementation
of the upload pipeline in
[`xob0t/gotohp`](https://github.com/xob0t/gotohp) (reference commit `2a5c1b9`).
The Rust library is also exposed as a standalone CLI, so the same protocol code
runs in both front ends.

## What is implemented

| Feature | Status | Where |
|---|---|---|
| Shared `gotohp.config` (YAML, same keys as upstream koanf tags) | working | `rust/src/core/config.rs` |
| Credentials: raw query string, Embedded Setup `oauth_token` exchange, select/remove/test | working | `rust/src/core/auth.rs` |
| Bearer-token refresh from master token, 30-min-style expiry cache | working | `rust/src/core/api.rs` |
| SHA-1 hashing, remote-hash dedup, upload-session token, streaming chunked PUT with retries + progress | working | `rust/src/core/{api,upload}.rs` |
| Commit (`CreateMediaItems`), media-key parse | working | `rust/src/core/api.rs` |
| Albums (named album from uploaded media keys; AUTO = one album per source dir) | working | `rust/src/core/{api,upload}.rs` |
| File discovery, supported-extension filter, recursive scan, exclude dir, canonical-path dedup | working | `rust/src/core/upload.rs` |
| Date from filename (upstream's four regex patterns) | working | `rust/src/core/upload.rs` |
| GUI: Pixie shell with sidebar, minimal upload screen, dedicated settings bar, accounts and about pages, live progress | working | `lib/` |
| Themes: System / Light / Dark and Violet / Teal / Rose / Ocean accents, persisted locally | working | `lib/theme_controller.dart` |
| CLI: `upload`, `creds add/list/set/remove`, `version` | working | `rust/src/bin/cli.rs` |
| Live Photo pairing + `CreateMediaItems` linked-item commit | **not ported** | see "Gaps" |
| Token binding (ADB alias read, Tink hybrid decrypt, ECDSA assertion JWT) | **not ported** | see "Gaps" |

The wire schemas in `rust/proto/` are copied verbatim from the reference
repository's `.proto/` directory. Endpoint URLs, hardcoded device fingerprint
(`Pixel XL`, `49029607`, `androidApiVersion 28`), request headers and header
values (`x-goog-ext-...`) likewise come from `core/api.go` at that commit.
Nothing here was guessed from a different Google Photos version.

## Layout

```
lib/                       Flutter UI (hand-written)
lib/src/rust/              Generated by flutter_rust_bridge — never edit
rust/src/api/              Bridge DTOs + functions exposed to Dart
rust/src/core/             Protocol, config, auth, uploader (pure Rust)
rust/src/bin/cli.rs        gotohp-rs-cli
rust/proto/                Wire schemas copied from reference client
rust/build.rs              prost-build
rust_builder/              cargokit build glue (generated)
```

## Design language

Derived from the reference material in `~/Downloads/inspo`: editorial white/dark
cards with bold oversized figures and small uppercase micro-labels (both
`desdivj` stills), a three-part workflow-health bar and legend (second still),
a sectioned sidebar with active pill rows and system section at the bottom
(`jahidul`), a dot matrix for per-file outcomes and a dark rounded score panel
(`uiuxjosh`), plus the motion shown in the three videos: counting numbers, a
progress ring, an expanding task card with step timings, and a dark pill toast
with an action.

## Interface

- **Sidebar** — Upload, Settings, Accounts, About. Collapses to a bottom bar on narrow windows.
- **Settings bar** — Appearance / Upload / Advanced tabs on the Settings page.
- **Branding** — the supplied Pixie mascot is bundled at `assets/pixie_logo.png` and used in the sidebar, the drop-zone empty state, the About page and the Android launcher icon.
- **Themes** — cycle with the sun icon in the app bar, or pick mode and accent under Settings → Appearance. Choices survive restarts via `shared_preferences`.
- **Minimal upload screen** — drop zone, queue chips, album field, compact counters and an activity panel that only appears once a run starts.
- **Preflight** — the queue is measured before upload (file count + total bytes), with size/speed/ETA during a run.
- **Queue persistence** — paths, album name and AUTO mode survive restarts via `shared_preferences`.
- **UX review pass** — short icon tabs in Settings, full-width ellipsised emails with an overflow menu, compact empty stats, mobile "Select photos" area, single primary Upload button, per-file thumbnails, pause/resume (Rust-backed), a meaningful tappable status pill, haptics, and an About page with changelog, updates, feedback, licenses and copy-debug-info.
- **Rust-owned telemetry** — preflight file sizing, progress totals, elapsed time, speed and ETA are computed in `rust/src/core/upload.rs` and exposed through `previewFilesDetailed()`, `getProgress()` and `coreInfo()`. The About page reads the live crate version, bridge version and target from Rust.
- **Dark theme** — layered near-black surfaces, lighter accent, brighter semantic green/amber/red and softer outlines for contrast.
- **Motion** — animated page transitions, drop-zone hover scale, expanding progress/activity panels and theme-change snackbars.
- **Keyboard** — Ctrl+U starts an upload, Ctrl+, opens settings.
- **Album AUTO** toggle on the upload screen; real per-worker IDs in Activity (fixed in the Rust pool).

## Build

Toolchain used here: Flutter 3.50.0 / Dart 3.14.0, rustc 1.99.0,
`flutter_rust_bridge_codegen` 2.13.0 (all three FRB versions must match:
codegen, `pubspec.yaml`, `rust/Cargo.toml`). `protoc` is required for
`prost-build` (36.1.0 used here).

```bash
flutter_rust_bridge_codegen generate   # after editing rust/src/api
cargo test --manifest-path rust/Cargo.toml
flutter test integration_test -d linux
flutter build linux --release
flutter build apk --release                                  # universal, ~63 MB
make build-apk-arm64                                          # arm64 only, ~23 MB
cargo build --release --manifest-path rust/Cargo.toml --bin gotohp-rs-cli
```

Android needs JDK 21. Java 27 fails Gradle 9.5.0 with
`Unsupported class file major version 71`. `.mise.toml` pins 21 for this
project; without mise use `flutter config --jdk-dir=<jdk-21>`.

## CLI

```bash
CLI="cargo run -q --manifest-path rust/Cargo.toml --bin gotohp-rs-cli --"

$CLI --config ./gotohp.config creds add "<oauth_token cookie value>"
$CLI --config ./gotohp.config creds add "androidId=...&Email=...&Token=..."
$CLI --config ./gotohp.config creds list
$CLI --config ./gotohp.config creds set user@gmail.com
$CLI --config ./gotohp.config upload /path/to/photos --recursive --threads 5
$CLI --config ./gotohp.config upload /path --album "Trip" --force
```

`--config` is optional. Without it the portable-file rule from the reference
client applies: an existing `gotohp.config` next to the executable or in the
working directory wins, otherwise `$XDG_CONFIG_HOME/gotohp/gotohp.config`.
Credentials written by the CLI are readable by the original gotohp GUI and
vice versa, because the file layout and query-string format are identical.

## Embedded credential

`rust/src/core/embedded.rs` contains a build-time credential captured from the
Google Photos GmsCore logcat request, with `androidId` replaced by the real ID
of the connected device. `init_app()` installs it into `gotohp.config` and
selects it on every startup, so the app opens ready to upload and the CLI needs
no `creds add`. Anything stored under the same email is replaced on startup.

The token is plaintext in both the source and the compiled binary — anyone with
the APK can extract it. To remove it, set `EMBEDDED_CREDENTIAL` to `""` and
rebuild, or sign out and back in on the phone to invalidate the token.

## Gotchas

- `flutter test test/` cannot load the native library; bridge tests live in
  `integration_test/` and need `-d linux` (or a device).
- Codegen never deletes orphaned Dart files. If a Rust API module is removed,
  delete its stale `lib/src/rust/api/*.dart` by hand.
- `pairLivePhotos`, `skipIncompleteLivePhotos` and
  `updateExistingPhotosToLive` are persisted for config compatibility but have
  no effect yet, since Live Photo pairing is not ported.
- A credential containing `token_binding_alias` is rejected at token refresh
  with an explicit error; use a credential with `assertion_jwt` already present
  or an Embedded Setup token.

## Gaps / next work

1. **Live Photos.** Port `core/livephoto.go`, `livephoto_metadata.go` (Apple
   content identifiers and QuickTime metadata) and `livephoto_upload.go`, then
   build `CreateMediaItemsRequest` with `LivePhotoInfo` / `ReconcileInfo`
   from `proto/CreateMediaItems.proto`. The protobuf message is already
   compiled by `build.rs`.
2. **Token binding.** Port the ADB alias extraction (`configmanager.go`) and
   the Tink hybrid / ECDSA assertion JWT (`tokenbinding.go`); Rust needs
   `tink-crypto` equivalents or a direct implementation of the hybrid scheme.
3. **Live-target verification.** No Google account or Android device/emulator
   was available in this session, so no request was sent to Google and the APK
   was not launched. Endpoint/header correctness is
   derived from the reference source, not from an observed successful upload.

## Status

Rust unit tests: 10 passed. Flutter integration tests on Linux: 2 passed.
`flutter analyze`: no issues. `flutter build linux --release` and
`flutter build apk --release`: both succeeded. The universal APK (65.2 MB)
contains `libgotohp_core.so` for arm64-v8a, armeabi-v7a and x86_64; the
arm64-only APK (22.9 MB) contains only arm64-v8a libraries. Gradle emits a
non-fatal warning that `desktop_drop` still applies the Kotlin Gradle Plugin.
CLI smoke tests for `version`, `creds add/list` against a temporary config:
succeeded. The UI includes stat tiles, account/preferences cards, a drop zone,
queue chips, per-thread progress and a results list.
